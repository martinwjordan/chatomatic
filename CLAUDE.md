# Chatomatic — Claude Code Project Context

## What this is

A web-based chatbot that replaces a traditional static website for a holiday home lent repeatedly to friends. Guests visit the URL and ask natural language questions about the property; the bot answers from a structured Markdown knowledge base. The owner reviews a daily email digest of questions to improve the knowledge base over time.

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Backend | Node.js / Express | Single-process, easy to maintain solo |
| Frontend | Plain HTML/CSS/JS | No build step, no framework overhead |
| AI | Claude Haiku 4.5 (`claude-haiku-4-5-20251001`) | Fastest/cheapest model appropriate for document Q&A; 4x cheaper than Sonnet |
| Prompt strategy | Prompt caching — full `knowledge.md` in every request | Full doc accuracy + ~90% cost reduction after first request per cache window |
| API response | Non-streaming, structured JSON `{ answer, suggestions }` | Enables suggested follow-ups in same call; Haiku fast enough that streaming isn't needed |
| Containerisation | Docker via QNAP Container Station | Runs on owner's QNAP NAS; `restart: always`; volumes for data persistence |
| Email | Nodemailer + Gmail SMTP | Daily digest of questions to owner |
| Rate limiting | express-rate-limit — 30 requests/IP/hour | Protects Claude API spend on this public-facing app |

## Knowledge base format

`data/knowledge.md` — YAML frontmatter block followed by Markdown sections:

```markdown
---
house_name: Honeysuckle Cottage
owner_contact: owner@email.com
suggested_questions:
  - What's the Wi-Fi password?
  - Where should we park?
  - What time is checkout?
  - Any good restaurants nearby?
arrival_brief:
  - "🔑 Keys: leave on the kitchen hook when you go out"
  - "🌡️ Heating: thermostat in the hallway, default 20°C"
  - "🗑️ Bins: black bin Tuesday · recycling Friday"
  - "📶 Wi-Fi: CottageGuest / [password]"
  - "📞 Owner: [mobile] if anything urgent"
---

## Wi-Fi
Network: CottageGuest | Password: sunflower22

## Alarm Code [RESTRICTED]
The alarm code is 4821. Set it when leaving.

## Local Restaurants
The Fox & Hound is a 5-minute walk...
```

**`[RESTRICTED]` rule:** Any heading containing `[RESTRICTED]` means the bot acknowledges the topic exists but never reveals content. Enforced by system prompt, not by access control.

**`arrival_brief`:** Rendered directly in the frontend (not passed through Claude) when the guest taps "I've arrived". Must be self-contained bullet points — no cross-references.

## Key design decisions

- **Public access, no login** — rate limiting (30 req/hr per IP) is the only protection
- **Conversation context** — last 3 exchanges (6 messages) per request; in-session only, not persisted
- **Unanswerable questions** — bot says "I'm not sure — ask the owner" and logs with `answered: false`
- **No streaming** — API returns structured JSON `{ answer, suggestions }`; Haiku is fast enough
- **Suggested follow-ups** — Claude returns up to 3 contextual follow-up questions with every answer; rendered as green chips below the bot's response
- **"I've arrived" button** — amber button in header; tapped once, delivers `arrival_brief` as bot message, sets `localStorage.chatomatic_arrived`, button disappears permanently on this device; arrival brief is rendered from frontmatter directly, not via Claude API
- **Knowledge base updates** — owner edits `knowledge.md` on NAS, restarts container; no rebuild needed
- **Digest frequency** — daily at 07:00 server time via node-cron (configurable via `DIGEST_CRON` env var)

## Routes

| Method | Path | Description |
|---|---|---|
| `GET` | `/` | Serves `public/index.html` |
| `POST` | `/api/chat` | Rate-limited; calls Claude; logs question |
| `GET` | `/api/starters` | Returns `house_name`, `suggested_questions`, `arrival_brief` |
| `GET` | `/health` | `200 OK` for Docker health check |

## Deployment (QNAP NAS)

- **Container Station** — runs Docker container; `restart: always`
- **QNAP Application Portal** — SSL termination + reverse proxy → port 3000
- **QNAP DDNS** — provides public URL; port 80/443 must be forwarded from router
- **`data/` volume** — mounted from NAS filesystem; `knowledge.md` and `questions.log` persist across restarts and rebuilds
- **`.env`** — holds `ANTHROPIC_API_KEY`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `DIGEST_EMAIL`; never committed

## Scripts

```bash
# Initial setup — convert Word doc to structured knowledge.md
node scripts/ingest.js "House Guide.docx"
# → mammoth extracts text → Claude structures it → writes data/knowledge.md
# → review output, adjust [RESTRICTED] tags and arrival_brief, then deploy

# Periodic — identify knowledge gaps before updating the knowledge base
node scripts/analyze-gaps.js
# → reads knowledge.md + questions.log → Claude identifies gaps → writes GAPS.md
# → review GAPS.md, update knowledge.md accordingly, restart container
```

## Claude API usage notes

- Model: `claude-haiku-4-5-20251001`
- Prompt caching: system prompt + knowledge block both marked `cache_control: { type: "ephemeral" }`
- Keep `knowledge.md` under ~15,000 tokens for optimal caching
- Pass last 3 exchanges as history; trim client-side
- Response format: `{ "answer": "...", "suggestions": ["...", "...", "..."] }`
- Arrival brief is NOT sent through Claude — rendered directly from frontmatter

## Question log format

`data/questions.log` — JSON lines, one per question:

```jsonl
{"ts":"2026-05-13T10:22:00Z","q":"What's the Wi-Fi password?","answered":true,"restricted":false}
{"ts":"2026-05-13T11:05:00Z","q":"What's the alarm code?","answered":false,"restricted":true}
{"ts":"2026-05-13T14:30:00Z","q":"Is there a kayak?","answered":false,"restricted":false}
```

`answered: false, restricted: false` = prime candidate for knowledge base addition.
